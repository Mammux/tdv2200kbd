TDV(1) General Commands Manual TDV(1)

NAME

tdv — configure the Tandberg TDV 2200 keyboard USB adapter

SYNOPSIS

tdv [-d serial] [-q | -v] command [argument ...]


tdv info

tdv list

tdv monitor [--raw] [--log]

tdv map [-l layer]

tdv get [-l layer] key

tdv set [-l layer] key action

tdv clear [-l layer] key

tdv led [led [source]]

tdv option [name [value]]

tdv send byte ...

tdv keys

tdv save | revert | defaults

tdv export [file]

tdv import [--save] file

tdv reboot | bootloader

tdv completions shell

DESCRIPTION

The TDV 2200 adapter is a Raspberry Pi Pico that connects a Tandberg TDV 2200 terminal keyboard (Norsk Data ND 320) to a computer over USB. To the computer it is an ordinary USB keyboard. tdv talks to the adapter over a separate USB interface, so it can change the key map and other settings while the keyboard is in use, without restarting it or installing a driver.

Changes take effect at once but are kept only in the adapter's memory until tdv save writes them to its flash. Unplugging the adapter before that brings back the saved settings.

Keys

A key is a position on the TDV 2200 keyboard. It can be given as the position name from the layout document, such as G51 or C1, or as the key's legend, such as FUNK or HJELP. Case does not matter. Legends with more than one word can be given by their first word (EKSP) or quoted in full (EKSP INNS). Number pad keys are written with np, as in 7np. A legend that appears more than once, or that matches a position name, is refused; use the position name instead. tdv keys lists every position with its legend.

The four keys in the modifier column are named CAPS, CTRL, LOCK and SHIFT.

Actions

An action says what a key sends.

usage
A USB keyboard key, by name: A, 1, Enter, Escape, Backspace, Tab, Space, F1 to F24, Up, PageDown, Home, Insert, Delete, CapsLock, NonUSBackslash and so on, or as a number from the USB HID keyboard page, 0x68. tdv set --help lists the names. Keys are named by their position on a US keyboard; the computer's keyboard layout decides which character they type.
modifier+usage
A key together with modifiers, for example Ctrl+C or Cmd+Shift+4. Modifiers are Ctrl, Shift, Alt (or Option), Gui (or Cmd, Win), and AltGr (right Alt); each can be prefixed with Left or Right.
modifier
A modifier on its own, such as LeftAlt: the key then works like that modifier key.
media
A media key: Mute, VolumeUp, VolumeDown, PlayPause, NextTrack, PreviousTrack, BrightnessUp, BrightnessDown.
layer:N
Switches to layer N while the key is held.
toggle:N
Switches layer N on or off each time the key is pressed.
text:string
Types string when the key is pressed. Only characters on a US keyboard can be typed this way.
seq:action,action ...
Sends several keys one after another, for example seq:Ctrl+A,Delete.
none
The key sends nothing.

Quote actions that contain spaces or characters the shell treats specially.

Layers

There are four layers, numbered 0 to 3. Layer 0 is the normal key map. While a higher layer is active, a key that has an action on that layer sends it; a key with no action there sends its action from the layer below. Commands that take -l layer use layer 0 when it is left out.

COMMANDS

info
Shows the firmware version, the USB serial number, whether there are unsaved changes, and the active layer.
list
Lists the adapters that are plugged in, by serial number.
monitor [--raw | --log]
Shows each key event as it happens, until interrupted with Ctrl-C: time since the previous event, the byte from the keyboard, press or release, the key's position and legend, and what was sent to the computer. 
+  1250 ms  2f  press    G51  FUNK            -> F13
+    96 ms  af  release  G51  FUNK            -> F13
+   310 ms  00 70        SHIFT down           -> LeftShift

With --raw, shows only the bytes from the keyboard, as the original sniffer did. With --log, also shows the adapter's log messages.

map [-l layer]
Prints the key map of layer as a table of position, legend and action, with a mark on keys changed from the default.
get [-l layer] key
Prints what key sends.
set [-l layer] key action
Makes key send action.
clear [-l layer] key
On layer 0, gives key back its default action. On a higher layer, removes the key's action there, so it sends what it sends on the layer below.
led [led [source]]
Without arguments, shows what each LED shows. With led and source, makes the LED show that state. led is 1 to 8, caps or lock. source is one of the computer's lock states, caps, num, scroll, compose or kana; layer:N for an active layer; or on or off. By default the Caps LED shows the computer's Caps Lock state and the others are off.
option [name [value]]
Without arguments, lists the options and their values. With name, shows one; with value as well, changes it.
click on | off
Key click from the keyboard's beeper on each key press. Default off.
layer-beep on | off
A beep when a layer is toggled on or off. Default off.
send byte ...
Sends command bytes, in hexadecimal, straight to the keyboard, for example tdv send 24 to beep. See docs/protocol.md for the commands. After 20 (reset) the adapter turns raw mode back on by itself. Sending 36 (raw mode off) to a keyboard with the patched original ROM makes it send characters the adapter cannot translate, until 31 is sent or the adapter is plugged in again.
keys
Lists every key position with its legend and USB default.
save
Writes the current settings to the adapter's flash, so they are used from the next time it is plugged in.
revert
Throws away unsaved changes and goes back to the saved settings.
defaults
Replaces the current settings with the built-in defaults. Use save afterwards to keep them.
export [file]
Writes all settings, including unsaved changes, as a TOML file, or to standard output if file is left out.
import [--save] file
Reads settings from a TOML file written by export or by hand. Settings the file leaves out keep their defaults. With --save, also saves them. A file with any error is refused as a whole.
reboot
Restarts the adapter. Unsaved changes are lost.
bootloader
Restarts the adapter into the Pico's UF2 bootloader, where it shows up as the RPI-RP2 drive, ready for new firmware.
completions shell
Prints a completion script for shell: bash, zsh, fish or powershell.

OPTIONS

-d serial, --device serial
Uses the adapter with this serial number, as shown by list. Needed only when more than one adapter is plugged in.
-l layer, --layer layer
The layer, 0 to 3, for map, get, set and clear.
-q, --quiet
Prints only errors.
-v, --verbose
Also prints what is sent to and received from the adapter.
-h, --help
Prints help for tdv or for a command.
-V, --version
Prints the version of tdv.

FILE FORMAT

export and import use TOML. Keys are named by position, and actions are written as for set.

# tdv export, firmware 0.2.0
version = 1

[layer.0]
G51 = "F13"            # FUNK
C99 = "LeftAlt"        # Squiggle
G1  = "text:make\n"

[layer.1]
C8  = "Up"             # K
B4  = "Mute"           # V

[modifiers]
LOCK = "toggle:1"

[leds]
caps = "caps"
1    = "layer:1"

[options]
click = false

ENVIRONMENT

TDV_DEVICE
Serial number of the adapter to use, as for -d.

EXIT STATUS

0
Success.
1
The adapter refused the command or reported an error.
2
Wrong arguments, an unknown key or action, or an invalid file.
3
No adapter found, or more than one and no -d.
4
The adapter's firmware is too old or too new for this version of tdv.

EXAMPLES

Make FUNK send F13, so the computer can bind it to anything:

tdv set FUNK F13

Use LOCK to toggle layer 1, with the arrow keys on HJKL there, and LED 1 lit while layer 1 is on:

tdv set LOCK toggle:1
tdv set -l 1 H Left
tdv set -l 1 J Down
tdv set -l 1 K Up
tdv set -l 1 L Right
tdv led 1 layer:1
tdv save

Volume keys on P7 and P8:

tdv set P7 VolumeDown; tdv set P8 VolumeUp

Keep a copy of the settings, then start again from the defaults:

tdv export > tdv.toml
tdv defaults
tdv save

Find out what a key sends, by watching while pressing it:

tdv monitor

RECOVERY

If a setting makes the keyboard unusable, hold ESC while plugging the adapter in. It then starts with the built-in defaults and ignores the saved settings until save is used again.

NOTES

On Linux, using the adapter without root needs a udev rule, for example in /etc/udev/rules.d/70-tdv2200.rules:

SUBSYSTEM=="usb", ATTR{idVendor}=="1209", ATTR{idProduct}=="0001", \
  TAG+="uaccess"

On Windows the adapter's descriptors make Windows load its WinUSB driver by itself. macOS needs nothing.

HISTORY

This page was written before tdv and describes how it is meant to work. Until the Rust firmware reaches milestone 4, the adapter runs firmware without the configuration interface, and tdv cannot find it.

BUGS
